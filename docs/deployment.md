# Deployment

The public demo runs on [Render](https://render.com) from the Blueprint in
[`render.yaml`](../render.yaml):
https://spanscope-llm-observability-dashboard.onrender.com/

## Deploy your own

1. Sign in to Render with GitHub and give it access to this repository.
2. Choose **New → Blueprint**, select the repository, branch `main`, and leave
   **Blueprint Path** empty (it defaults to `render.yaml` in the repo root).
3. Give the Blueprint any name and click **Deploy Blueprint**.
4. After 2–4 minutes the service shows **Live**. Its URL is at the top of the
   service page.

Every push to `main` redeploys automatically (`autoDeploy: true`). Check a
deploy with:

```bash
curl https://<your-service>.onrender.com/healthz
```

which returns `{"status":"ok","storage":"memory",...}`.

## What the Blueprint sets

| Setting | Value | Why |
|---|---|---|
| `plan` | `free` | Costs nothing; see the free plan notes below |
| `rootDir` | `dashboard` | The Node app lives there |
| `buildCommand` | `npm ci --include=dev` | `tsx`, which runs the TypeScript server, is a dev dependency |
| `startCommand` | `npm run serve` | Starts the web app and ingest server |
| `healthCheckPath` | `/healthz` | Render restarts the service if this fails |
| `NODE_VERSION` | `22` | Matches `.nvmrc` |
| `HOST` | `0.0.0.0` | Accept connections from Render's proxy. Render sets `PORT` itself |
| `DEMO_MODE` | `1` | Visitors can't clear the data for everyone else |
| `LIVE_TRAFFIC_PER_MIN` | `30` | Synthetic traffic keeps the charts moving |
| `INGEST_RATE_LIMIT_PER_MIN` | `60` | Caps send requests per visitor IP |
| `PUBLIC_URL` | the service URL | Only used by the optional sign-in |
| `SESSION_SECRET` | generated by Render | Only used by the optional sign-in |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | not set | Leaving them unset keeps sign-in off |

Storage is the default in-memory ring buffer. Render's free plan has no
persistent disk and can't run ClickHouse, so the demo doesn't use it.

## Free plan behaviour

- The service sleeps after 15 minutes without visitors. The next visit takes
  30–60 seconds while it wakes, then it's fast. A paid instance (about
  $7/month) stays awake.
- Data is held in memory, so it resets on every wake, restart and deploy. The
  server reloads an hour of generated history each time.
- If the API doesn't answer while the server wakes, the web app shows
  **Try again**.

## The service name is the URL

Render builds the `onrender.com` address from the service name in
`render.yaml` (adding a few random characters if the name is taken), and an
existing service's address can't be changed. Renaming the service in
`render.yaml` therefore creates a new service with a new URL; delete the old
one in Render afterwards (Settings → Delete Web Service), and update any links
to it first.

This project went through that once: the service was first deployed as
`llm-observability-dashboard` and is now `spanscope-llm-observability-dashboard`.
The GitHub repository was renamed to `Spanscope-LLM-observability-dashboard` at
the same time; GitHub redirects the old repository URL.

For a shorter, permanent address, add a custom domain in Render (Settings →
Custom Domains). It points at the existing service, so the `onrender.com` link
keeps working.

## Sign in with GitHub (optional)

**The public demo deliberately has no sign-in** so that anyone, recruiters
included, can use every feature immediately (see
[decisions.md](decisions.md#7-the-public-demo-has-no-sign-in)). Abuse is limited
by demo mode and the per-IP rate limit instead.

The server supports Sign in with GitHub. When it's on, viewing stays public
but simulating incidents, sending data and clearing need a signed-in user or a
personal ingest key. To turn it on:

1. Create a GitHub OAuth app at
   [github.com/settings/applications/new](https://github.com/settings/applications/new):
   - **Homepage URL**: your service URL
   - **Authorization callback URL**: `<service URL>/auth/github/callback`
2. Copy the **Client ID**, then generate and copy a **client secret**.
3. In Render, open the service → **Environment**, add `GITHUB_CLIENT_ID` and
   `GITHUB_CLIENT_SECRET`, check that `PUBLIC_URL` and `SESSION_SECRET` are set,
   and choose **Save, rebuild, and deploy**.
4. Check: `GET /api/me` returns `"authEnabled": true`, and the header shows a
   **Sign in** button.

To turn it off again, delete `GITHUB_CLIENT_ID` and `GITHUB_CLIENT_SECRET`.
Changing `SESSION_SECRET` signs everyone out and invalidates every ingest key.

Never commit these values or paste them anywhere but GitHub and Render. For
local testing, create a second OAuth app whose callback is
`http://localhost:8011/auth/github/callback`; an OAuth app has only one
callback URL.

How sign-in works is described in the [API reference](api.md#sign-in-optional).

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| Blueprint says "`render.yaml` not found on main branch" | The file isn't on `main` yet. Push it, then click **Retry** |
| First visit hangs for up to a minute | Normal cold start on the free plan |
| Deploy fails at start-up with a config message | An environment variable is invalid; the log names it (for example `PORT must be an integer >= 1`) |
| Deploy fails with `SESSION_SECRET must be at least 32 characters` | Sign-in is half configured. Set a longer `SESSION_SECRET`, or remove the GitHub values |
| GitHub says "The redirect_uri is not associated with this application" | The OAuth app's callback URL doesn't match `PUBLIC_URL` + `/auth/github/callback` |
| Visitors get `429 rate_limited` | More than `INGEST_RATE_LIMIT_PER_MIN` send requests from one IP in a minute; raise the value if needed |
